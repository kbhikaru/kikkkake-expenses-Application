# 経費申請アプリ 設計書

## 1. 目的と方針

- Googleフォームのファイルアップロードが共有ドライブで使えない問題を、GAS Webアプリで置き換えて解消する
- 社員（KIKKAKE）とバリスタ（TIE Coffee）のフォームを **所属区分** で一本化する
- 1申請 = freeeの1取引 になるようにデータを持ち、CSV / API どちらでもそのまま連携できるようにする
- 管理者はコードを触らずに、フォーム項目・選択肢・マスタ・保存先を画面から変更できる

## 2. GASの構成

| | 申請者用 | 管理者用 |
|---|---|---|
| 種類 | コンテナバインド（経費DBスプレッドシートの拡張機能） | 単独プロジェクト |
| 公開 | Webアプリ（実行：オーナー / ドメイン内） | Webアプリ（実行：オーナー / ドメイン内）＋パスワード |
| 主なファイル | `Main.gs`（申請・保存）, `LegacyImport.gs`, `Index/Styles/App.html` | `Auth.gs`, `AdminApi.gs`, `Freee.gs`, `Admin/AdminStyles/AdminApp.html` |
| 共通 | `SharedSchema.gs`（列定義・初期値）, `SharedStore.gs`（読み書き） | 同左 |
| ホームの特定 | `SpreadsheetApp.getActiveSpreadsheet()` | スクリプトプロパティ `HOME_SPREADSHEET_ID` |

**なぜ分けるか**
- 申請者用URLを知っていても管理機能には一切アクセスできない（関数自体が存在しない）
- 管理者パスワード・freeeのトークンは管理者用プロジェクトのスクリプトプロパティにだけ保存され、スプレッドシートの編集者からも見えない
- 設定・マスタはホームのスプレッドシートに置くので、管理画面で変えた内容が即座に申請画面へ反映される

### 3.3 従業員マスタの参照

`【マスタ】会社全体_KIKKAKE` の「従業員」シートから **社員ID・氏名・部署・チーム・稼働ステータス の4列だけ** を読みます。
マイナンバーや口座情報など他の列は画面にもサーバー応答にも一切含めません。
稼働ステータスが「退職」の人は選択肢から除外します（設定 `EMPLOYEE_EXCLUDE_STATUS`）。

## 4. 税区分とインボイス

| 申請画面の税率 | 適格請求書あり | なし・不明（2026/10〜2029/9） |
|---|---|---|
| 10% | 課対仕入10%（136） | 課対仕入（控50）10%（190） |
| 8%（軽減） | 課対仕入8%（軽）（163） | 課対仕入（控50）8%（軽）（188） |
| 非課税 | 非課仕入（37） | 非課仕入（37） |
| 対象外 | 対象外（2） | 対象外（2） |

2029/10 以降は経過措置が終わるため、税区分マスタの「非適格」列を変更してください。

消費税額は freee の既定（切り捨て）に合わせて `floor(税込 × 税率 / (100 + 税率))` で計算します。
旧フォームのシートは税抜を切り捨てていたため、800円の場合 旧：税抜727/税73 → 新：税抜728/税72 と1円ずれます。

## 5. freee連携

### 方式A：CSV（おすすめ・設定不要）
管理画面「freee連携」で期間を指定して出力 → freee会計［取引の一覧・登録 → 取引のインポート］で取込。
取込画面で列の対応付けを確認してください。出力した申請は「freee連携済」になり、二重出力を防ぎます。

- 立替：`FREEE_SETTLEMENT_ACCOUNT` が空欄なら **未決済** で登録 → 精算時に freee で消込
- 会社カード / 現金：`FREEE_CARD_ACCOUNT` / `FREEE_CASH_ACCOUNT` に freee の口座名を入れると決済済みで登録

### 方式B：API
1. freee アプリストアで開発アプリを作成、コールバックURLに管理画面に表示されるURLを登録
2. 管理画面で Client ID / Secret を保存 →「freeeと連携する」
3. 「マスタ同期」で勘定科目ID・税区分コード・部門を取得
4. 「承認済をfreeeに登録」で取引を作成し、領収書を証憑として添付（1回20件ずつ自動で繰り返し）

## 5.1 月次精算書とfreeeへのまとめ登録

1件ずつfreeeに登録する手間をなくすため、**支払者×月 = 1精算書 = freee 1取引** にまとめます。

| 項目 | 内容 |
|---|---|
| 精算書番号 | `STMT-yyyyMM-社員ID`（freeeの管理番号 / `ref_number`） |
| 対象 | 対象月（`RECEIPT_MONTH_BASIS`）の「承認済」「freee連携済」。`STATEMENT_INCLUDE_PENDING=はい` で申請中も含める |
| 明細 | No・支払日・支払先・内容・勘定科目・税区分・金額・消費税・支払方法・適格請求書・申請ID・**領収書リンク**・**元データリンク**・ステータス |
| 保存 | 月フォルダに一覧スプレッドシート＋PDF、社員フォルダに個人の精算書PDF。作り直すと同名ファイルはゴミ箱へ移して上書き |
| 経費データ | 「精算書番号」「精算書URL」列に記録（freee登録時のまとめ単位になる） |
| freee取引 | 発生日＝対象月の月末、取引先＝支払者、明細＝勘定科目×税区分×部門ごとに合算、証憑＝精算書PDF |
| 自動作成 | 時間主導トリガーで毎月 `STATEMENT_AUTO_DAY` 日に前月分を作成し `NOTIFY_EMAILS` に通知 |

**電子帳簿保存法の観点**：freeeに添付するのは精算書PDFですが、領収書の原本（電子データ）は Drive に申請時のまま残り、
精算書の各明細・経費データ（日付・金額・支払先で検索可能）からたどれるようにしています。
領収書ファイルは削除・上書きしない運用にしてください（Driveの版管理・変更履歴が残ります）。

## 5.2 アーカイブ（削除の代わり）

誤申請・二重申請は行を削除せず「アーカイブ」にします。

- ダッシュボード・月次精算書・freee連携・支払先候補の対象外。申請一覧の「すべて」にも表示しない
- データと領収書ファイルはそのまま残る。ステータス「アーカイブ」で絞り込み、「元に戻す」でアーカイブ前のステータスに復帰
- アーカイブ中の申請は承認・差戻しなどのステータス変更を受け付けない
- freee登録済み・精算書作成済みの申請をアーカイブすると注意を表示（freeeの取引は自動では消えない。精算書は作り直すと外れる）

## 6. セキュリティ

- 申請者用・管理者用とも「オーナーとして実行」。申請者には共有ドライブやスプレッドシートの権限は不要
- 管理者パスワードはソルト付きSHA-256を反復したハッシュのみ保存、5回失敗で15分ロック、セッション6時間
- 任意で管理者のGoogleアカウントを限定（パスワードとの二重チェック）
- アップロードは画像/PDFのみ・サイズ上限あり。スマホ写真はブラウザ側で長辺2000pxに縮小して送信

## 7. 今後の拡張案

- 申請者が自分の申請状況（差戻し理由など）を確認できる画面
- 差戻し時の申請者へのメール通知（申請者メールが取れる場合）
- freee の取引先（従業員）と紐づけて立替精算を自動消込
